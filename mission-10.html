Mission 10

Security Monitoring: turn logs into actionable detection.

BrightFuture systems generate logs, but no one has defined which events matter, how to find them, or when to escalate. Your team must build and test a small monitoring workflow.

AUTHORIZED COURSE SCENARIOMISSION 10

Situation

Collected logs create value only when they answer a security question.

The lab includes endpoint, authentication, network, or application events. The team needs a detection hypothesis, a search or filter, a test event, tuning, context, and an escalation path.

Mission objectives

  • Identify useful log sources, fields, retention needs, and time considerations.
  • Create searches, filters, correlations, or alert logic for a defined behavior.
  • Generate or use an approved benign test event to validate detection.
  • Tune false positives and write a repeatable analyst runbook and escalation process.

Use only the provided logs and approved lab events. Do not monitor another person, collect private communications, or generate disruptive activity.

Rules of engagementRequired
  • 01Define the detection purpose before writing the search.
  • 02Use only approved event sources and benign test actions.
  • 03Preserve raw logs and document transformations or filters.
  • 04Do not publish real usernames, addresses, tokens, or restricted log contents.
