Resource library

Quick references for course operations.

Each card identifies what the resource is for and the practices students should follow while using it.

01

Lab safety and scope

Rules for authorized use, evidence handling, privacy, and escalation.

  • Stay inside the assigned virtual environment
  • Use only instructor-provided targets
  • Remove real personal data from submissions
  • Stop when authorization is unclear
WS

Wireshark

Use packet captures to inspect conversations, protocols, addresses, timing, and suspicious patterns.

  • Identify endpoints and protocols
  • Apply display filters
  • Follow approved streams
  • Save evidence without exposing credentials
NM

Nmap

Use authorized discovery to identify hosts, ports, services, and changes in the isolated lab.

  • Confirm the scope first
  • Use conservative scan options
  • Record the command and timestamp
  • Validate findings before reporting
EV

Windows Event Viewer

Review authentication, system, application, and security events to support investigations.

  • Filter by time and event ID
  • Compare normal and suspicious activity
  • Export relevant events
  • Document timezone and system context
LX

Linux command line

Inspect processes, users, permissions, services, files, logs, hashes, and network state.

  • Use commands that preserve evidence
  • Explain each option used
  • Capture output in the report
  • Validate changes after hardening
OS

OpenSSL and hashing tools

Practice hashing, integrity verification, encryption, keys, and certificates with non-sensitive lab data.

  • Differentiate hashing and encryption
  • Protect private keys
  • Compare before and after hashes
  • Document algorithms and key choices
VM

Virtual lab

Use snapshots and isolated machines to test security changes without affecting school systems.

  • Create a checkpoint before major work
  • Label virtual machines clearly
  • Restore after destructive tests
  • Keep host and lab networks separated
ER

Evidence and reporting

Create reports that connect observations, conclusions, actions, validation, and remaining risk.

  • Use clear filenames and timestamps
  • Caption every screenshot
  • Separate facts from assumptions
  • Write both technical and executive summaries

Before using a security tool

Ask four questions.

This decision check should happen before scanning, changing, collecting, or sharing anything.

01

Am I authorized?

Confirm the target, account, network, time window, and allowed techniques.

02

What evidence do I need?

Know what must be recorded before a command or configuration change is made.

03

What could this affect?

Consider availability, privacy, data integrity, shared services, and other teams.

04

How will I validate the result?

Define what success, failure, rollback, and residual risk will look like.

Put the process to work

Begin with evidence, not assumptions.

Mission 01 uses inventory, classification, observations, and risk reasoning before any technical changes.
